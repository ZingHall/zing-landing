# Pay-Per-Query API

The Pay-Per-Query (PPQ) system enables AI agents and researchers to pay micro-fees for accessing specific Knowledge Graph triples. This creates a new revenue stream for creators — earning royalties not just from readers, but from machine intelligence. {{ className: 'lead' }}

<Note>
  **Status**: Pay-Per-Query is currently in development. The API endpoints below
  represent the planned implementation.
</Note>

## What is Pay-Per-Query?

Pay-Per-Query is a micro-transaction model where users pay a **fractional fee** for each specific piece of data retrieved by an AI:

- Traditional Content: Pay $X/month for all content
- Pay-Per-Query: Pay $0.001 per specific fact/triple accessed

This is particularly valuable for:

- **AI Agents** - Pay only for data they actually use
- **Researchers** - Access specific facts without full subscriptions
- **Developers** - Build applications on creator knowledge

## The Inseparability Principle

Every data blob stored on Walrus is cryptographically bound to a **Sui payment intent**. Access to the raw data by an AI agent is programmatically impossible without the execution of a Pay-Per-Query transaction.

## Initiate Query {{ tag: 'POST', label: '/v1/ppq/initiate' }}

<Row>
  <Col>

    Initiate a Pay-Per-Query transaction. Creates a payment intent and returns the amount to pay.

    ### Required attributes

    <Properties>
      <Property name="triple_ids" type="array">
        Array of triple IDs to query.
      </Property>
      <Property name="purpose" type="string">
        Description of how the data will be used.
      </Property>
    </Properties>

    ### Returns

    - Payment intent with exact fee amount
    - Creator address for the payment
    - Expiration time for the intent

  </Col>
  <Col sticky>

    <CodeGroup title="Request" tag="POST" label="/v1/ppq/initiate">

    ```bash {{ title: 'cURL' }}
    curl https://api.zing.protocol/v1/ppq/initiate \
      -H "Authorization: Bearer {jwt_token}" \
      -d triple_ids='["triple_001", "triple_002"]' \
      -d purpose="research"
    ```

    ```js
    const intent = await client.ppq.initiate({
      tripleIds: ['triple_001', 'triple_002'],
      purpose: 'research',
    });
    ```

    ```json {{ title: 'Response' }}
    {
      "intent_id": "intent_abc123",
      "total_fee": "0.002",
      "expires_at": 1709316000,
      "status": "pending"
    }
    ```

    </CodeGroup>

  </Col>
</Row>

## Execute Query {{ tag: 'POST', label: '/v1/ppq/execute' }}

<Row>
  <Col>

    Execute the Pay-Per-Query payment and receive the triple data.

    ### Required attributes

    <Properties>
      <Property name="intent_id" type="string">
        The payment intent ID from initiate.
      </Property>
    </Properties>

    ### How it works

    1. Verify USDC balance
    2. Execute Sui transaction for payment
    3. Atomic unlock of triple data
    4. Return decrypted content

  </Col>
  <Col sticky>

    <CodeGroup title="Request" tag="POST" label="/v1/ppq/execute">

    ```bash {{ title: 'cURL' }}
    curl https://api.zing.protocol/v1/ppq/execute \
      -H "Authorization: Bearer {jwt_token}" \
      -d intent_id="intent_abc123"
    ```

    ```js
    const result = await client.ppq.execute({
      intentId: 'intent_abc123',
    });
    ```

    ```json {{ title: 'Response' }}
    {
      "success": true,
      "tx_hash": "0xsui...tx_hash",
      "triples": [...]
    }
    ```

    </CodeGroup>

  </Col>
</Row>

## Fee Structure

| Query Type         | Fee          | Creator Share |
| ------------------ | ------------ | ------------- |
| Single triple      | $0.001       | 80% ($0.0008) |
| Bulk (10+ triples) | $0.0008 each | 80%           |

### Revenue Split

| Party             | Share |
| ----------------- | ----- |
| **Creator**       | 80%   |
| **Zing Protocol** | 20%   |

## Security Features

<Note>
  **Cryptographic Binding**: Each Walrus blob is bound to a payment intent.
  Without payment, the blob cannot be decrypted.
</Note>

<Note>
  **Attribution**: All queries are recorded in the Attribution Ledger for
  creator transparency.
</Note>

<Note>
  **Atomic Transactions**: Payment and data unlock happen in a single Sui
  transaction.
</Note>
