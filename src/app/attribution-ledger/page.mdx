# Attribution Ledger

The Attribution Ledger is an immutable record on Sui that links AI outputs back to specific Walrus Blob IDs. This ensures creators are properly credited whenever their content is used by AI agents. {{ className: 'lead' }}

<Note>
  **Status**: Attribution Ledger is currently in development. The API endpoints
  below represent the planned implementation.
</Note>

## Overview

Every time an AI agent queries and uses content from the Knowledge Graph, an immutable record is created:

```
AI Output → Attribution Ledger → Source Walrus Blob → Creator
     ↓
Immutable record ensures:
- Creator gets credited
- Usage is transparent
- Royalties are tracked
```

## The Attribution Record Model

### Properties

<Properties>
  <Property name="id" type="string">
    Unique identifier for the attribution record.
  </Property>
  <Property name="query_id" type="string">
    The Pay-Per-Query transaction ID.
  </Property>
  <Property name="triple_id" type="string">
    The knowledge triple that was accessed.
  </Property>
  <Property name="blob_id" type="string">
    The source Walrus blob ID.
  </Property>
  <Property name="creator" type="string">
    The creator's Sui address.
  </Property>
  <Property name="query_creator" type="string">
    The AI agent/researcher who queried.
  </Property>
  <Property name="usage_purpose" type="string">
    Declared purpose of the query.
  </Property>
  <Property name="created_at" type="timestamp">
    When the attribution was recorded.
  </Property>
  <Property name="fee_paid" type="string">
    The fee paid for this query.
  </Property>
</Properties>

## How Attribution Works

```
1. AI Agent initiates query
         ↓
2. Triple data unlocked via PPQ
         ↓
3. Attribution record created atomically:
   ┌────────────────────────────────────────┐
   │  ON-CHAIN ATTRIBUTION RECORD            │
   │                                         │
   │  triple_id → blob_id → creator         │
   │  query_id → query_creator              │
   │  purpose → fee_paid → timestamp       │
   └────────────────────────────────────────┘
         ↓
4. Record immutable on Sui blockchain
         ↓
5. Creator can view in dashboard
         ↓
6. Fees tracked for royalty reporting
```

## Royalty Tracking

Attribution records feed into the royalty system:

```typescript
// Creator royalty calculation
const royalties = {
  subscription_fees: '500.00', // From subscriptions
  donation_fees: '50.00', // From donations
  ppq_royalties: '1.25', // From AI attribution
  total: '551.25',
}

// 80% to creator, 20% platform
const creator_share = parseFloat(royalties.ppq_royalties) * 0.8 // $1.00
```

## Compliance

<Note>
  **Creator Consent**: Content on Zing Protocol is opt-in for Knowledge Graph
  inclusion. Creators choose which content to expose.
</Note>

<Note>
  **Immutable Records**: Attribution records cannot be altered or deleted,
  ensuring long-term auditability.
</Note>

<Note>
  **Transparent Fees**: All PPQ fees are tracked and traceable to specific
  content access.
</Note>
